pydle for teachers

pydle runs Python in the browser with no accounts, no installation and no licence. GitHub is optional, and it is the only part that needs setting up in advance.

What a lesson looks like

Students make a project, write Python and press Run. Python downloads once, then the editor, console and turtle work without a server. Work saves to that browser as they type, and any file downloads as a .py.

From year 9, GitHub should be the default. GitHub accounts are for people aged 13 and over. Do not create accounts for students. Students should not share accounts, otherwise their work will overwrite each other's.

Why not sign up in a lesson

GitHub rate-limits account creation by address and all students share an IP when working on school computers. There are documented cases of GitHub accounts signed up in lesson being suspended days later and taking weeks to restore. This is why setting up the GitHub account should always be done as homework using the student setup sheet.

  • Email. School filters quarantine GitHub's verification mail and some domains refuse external sign-ups. Students should sign up for GitHub outside of school using a personal email address. That way they will still own their code even after they've left school.

Before the lesson

  1. Check the network on a student device. It needs pydle.uk, cdn.jsdelivr.net, auth.pydle.uk and github.com, plus api.github.com for GitHub.
  2. Check the browser. A current Chrome, Edge, Firefox or Safari.
  3. Print the setup sheet one per student and hand it out a week ahead.

Students without GitHub work exactly as everyone else does.

What students get from GitHub

A private repository called pydle-workspace in their own account and each pydle project is a folder. This teaches git basics early and will pay dividends in future.

pydle implements a lite version of git. Rather than teaching branching, merging etc it only exposes the simple commit by commit workflow to get students used to the idea of version control. This also means they have a permanent record of their work after leaving school and if they go on to A-Level, using git is a great way to manage their coursework.

When the student authorises GitHub it grants the app read and write access to all repositories. pydle only touches the one it created, and pydle's code enforces that, not GitHub. Auth itself goes via an external Cloudflare worker. Nothing is stored off device.

Collecting work

  • Without GitHub, students download the .py and submit it as usual.
  • With GitHub, students add you as a collaborator on their repository. Give them this link with your username and it takes a minute each.
  • GitHub Classroom adds a class view on top of the same repositories.

Shared devices

Work belongs to the browser profile, so two students on one profile see each other's projects. Use a separate OS account or guest profile where you can. To clear a machine, delete the projects, press Forget this device, then clear site data for pydle.uk. Forget this device removes the sign-in only.

What pydle stores

  • No pydle accounts, no analytics and no tracking scripts.
  • Code stays in browser storage on the device until a commit (OPFS, with IndexedDB as a fallback).
  • The GitHub token is in that browser's IndexedDB, and Forget this device removes it.
  • Commits go to the student's own account. A private repository is visible to them and anyone they invite.
  • auth.pydle.uk relays GitHub's OAuth requests and stores nothing.

When it goes wrong

What happensWhat to do
The student cannot reach github.comSchool filtering. Check api.github.com too.
No verification emailJunk, then the school filter. Some domains block it outright.
"That code expired"The code lasts fifteen minutes. Start the sign-in again.
"The repository could not be created"The account already has pydle-workspace, or cannot create repositories. Check at github.com.
Signed in as someone elseForget this device, then sign in again.
Work has disappearedSaved work belongs to one browser profile. If they committed, signing in again brings it back.

Running your own copy

pydle is MIT licensed and static. Fork the repository and publish it on GitHub Pages or Cloudflare Pages, and the school has its own copy that does not depend on pydle.uk. Editing and storage work immediately. GitHub sync needs your own OAuth app and the relay set in js/config.js, which is the only part that needs maintaining. The steps are in docs/DEPLOY.md.
